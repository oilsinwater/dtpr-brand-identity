09 · Font Protocol

Where each family may and may not appear

Three families, one job each. The font protocol is the rule book — every visual decision that involves type is tested against it. The protocol is the page most often violated; treat it as the test for the type system.

MEMO

Public Sans — the working voice

Public Sans owns display, body, labels, button text, navigation, captions, and live-data indicator labels. If it is not editorial italic and it is not code, it is Public Sans.

Recommended
  • Headlines (h1–h3): Bold 700, 22–33px, 1.30 line-height.
  • Body copy: Regular 400, 17px, 1.64 line-height, 65–75ch max.
  • Labels (nav, button): SemiBold 600, 14px, 1.30 line-height.
  • Captions (timestamps, fine print): Regular 400, 12px, 1.40 line-height.
  • Live-data indicator label: SemiBold 600, 12px.
Avoid
  • Using Public Sans Italic for body emphasis. Use <em> tags for semantic emphasis; the visual default remains Regular.
  • Setting body copy below 16px or above 19px. Both ranges reduce legibility.
  • Setting headline weights below 600. Bold 700 is the minimum for h1–h3.
  • Tracking Public Sans above +0.02em in body. The font is designed for tight tracking.

Source Serif 4 Italic — the editorial moment

Source Serif 4 Italic appears exactly once per page, in the hero headline. This is the cadence rule.

Recommended
  • Hero headline only, 48px desktop / 36px mobile, line-height 1.15.
  • Italic 400 weight. The italic is the voice — not the weight.
  • Navy #1B2B80 on paper surfaces. White on dark surfaces.
  • One line if possible; two lines maximum.
Avoid
  • Using Source Serif 4 Italic in any other element on the page. Not in section headers. Not in CTAs. Not in cards. Not in the hero subhead. Not in navigation. Not in body copy.
  • Using Source Serif 4 in Roman (non-italic) style. The Roman is not part of the identity.
  • Combining Source Serif 4 Italic with another serif font. There is no second serif.
  • Setting the italic headline below 36px. Below this size, the italic loses its character.

Source Code Pro — code and taxonomy only

Source Code Pro is reserved for code blocks, schema identifiers, and taxonomy codes. Anywhere else, use Public Sans.

Recommended
  • Code blocks: Regular 400, 14px, 1.55 line-height, on Terminal Dark surface.
  • Schema identifiers (e.g., AI@2026-05-06-BETA): inline, 12–14px.
  • Taxonomy codes (e.g., 11 DATACHAIN LAYERS, 108 ELEMENTS): uppercase, JetBrains Mono or Source Code Pro.
  • Filename headers in code blocks: 12px, muted #94A3B8.
  • Copy-button label inside code blocks: 12px.
Avoid
  • Using Source Code Pro in navigation, button text, section headers, captions, or body prose.
  • Setting Source Code Pro below 11px. Below this, code is unreadable.
  • Applying Source Code Pro to non-code technical content. Live-data indicator labels, for example, use Public Sans SemiBold — they are UI labels, not code.
  • Mixing Source Code Pro with another monospace font. There is no second mono.

Cross-recipe protocol

Recipe B is the canonical direction. Recipes A (Regulatory) and C (Commons) are archived as experimental recipes; elements from them may inform Recipe B where they serve the Technical Evaluator, but they are no longer separate recipes in their own right. The recipes have been folded into Recipe B as optional registers (communications that read with some flavor of C or A), and supporting corpus material lives under recipes/b/corpus/.
